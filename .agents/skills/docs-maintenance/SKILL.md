# 文档维护 SOP

## 目录与命名

项目文档全部放在仓库根的 `docs/`，平铺，不建子目录。文件名用小写 kebab-case，扩展名 `.md`。`docs/README.md` 是唯一索引和阅读入口，列出其余全部文档。

## 文档头

每篇文档必须以 YAML frontmatter 开头，包含 `title` 和 `description`：

```markdown
---
title: 性格光谱与抽样
description: axes.yml 的轴定义、按目标等级抽样、人格定型与写入 pets.yml 的过程。
---
```

`title` 是两到八个字的主题名，用于索引和交叉链接。`description` 用一句话说明这篇文档记录什么，控制在 40 字以内，不复述 title，不写“本文介绍”之类的空话。两者都用中文标点，不加引号，避免出现 `: ` 以免破坏 YAML。

## 单主题原则

一篇文档只回答一个问题。判断标准是标题能否用一个名词短语概括，以及文中是否存在两个不共享前提的大节。出现第二个主题就拆成新文档，并在 `docs/README.md` 中登记。

拆分时保持每篇自洽：读者只读这一篇也能理解结论，需要背景时用相对链接指向另一篇，而不是复制内容。宁可多一篇短文档，也不写一篇“杂项”或“其他”。

## 内容标准

只写当前行为，不写变更历史、当前状态、后续计划或排查日志。配置项、路径、指令、默认值和示例必须与 `src/`、`build.gradle.kts`、`gradle.properties` 保持一致；改代码的同一次改动里同步文档。

不重复其他文档的细节，用相对链接代替。示例使用真实可运行的值，不写大段伪代码。内容过时时直接改写或删除，不用注释保留旧说法。

## 新增文档

1. 先在 `docs/README.md` 检索是否已有同主题文档。有就更新，主题变大就拆分。
2. 在 `docs/` 新建 `<topic>.md`，写 frontmatter 和正文。
3. 在 `docs/README.md` 的表格里按主题顺序插入一行，链接文字用 title。
4. 从相邻文档补相对链接，让新文档有入链。
5. 运行校验脚本。

## 更新文档

1. 先改正文，再检查 title 和 description 是否仍然准确。主题变化时必须改 description，它是路由信息。
2. 检查指向这篇和被这篇指向的文档是否受影响。
3. 运行校验脚本。

## 删除与合并

内容已被其他文档完整覆盖时删除，不留空文件或指路文件。删除后清理 `docs/README.md` 的条目以及所有入链。合并时保留描述更准确的一份，另一份直接删除，不保留重复段落。

## 禁止事项

不在仓库根新增 `INTRO.md`、`GUIDE.md` 之类的总说明书，入口只有 `docs/README.md`。不把多个主题塞进一篇文档。不在文档里记录 TODO、版本对比、逐步操作日志。

## 校验

```bash
bash .agents/skills/docs-maintenance/scripts/check-docs.sh
```

脚本检查：每篇文档有 frontmatter 和 title/description，description 不超过 60 字，README 索引覆盖全部文档且不指向不存在的文件。校验通过后再交付。
