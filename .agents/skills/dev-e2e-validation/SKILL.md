# 开发环境 E2E 验证

目标是用最少的真实副作用验证完整行为，同时让环境、云资源和故障注入都能恢复。只验证用户明确要求的范围；验证发现问题时，前端和后端都属于可诊断范围。

## 环境边界

- `.dev/` 保存开发配置、密钥、数据库和日志。不得读取、搜索或输出其中内容；应用可以自行加载，诊断者不要代读。
- 不把密码、密钥、Cookie、实例 IP、实例 ID 或完整运行日志写入技能、提交、回复或临时输出。
- `.dev` 只用于开发环境。未经明确授权，不操作生产环境、不创建真实云资源、不删除实例。
- 用户授权 E2E 创建或部署资源时，记录资源生命周期并在结束时询问是否清理；清理获得授权后必须验证资源确实消失。
- 遇到缺少 Docker、数据库、实例、权限或浏览器控制等问题时立即停止并报告，不要伪造实例、直接改数据库、绕过权限或自行扩大操作范围。

## 仓库与入口

- 后端仓库通常位于当前工作区，前端仓库为 `../go-aliyunmc-client-web`。
- 后端开发入口为 `make dev`，默认监听 `http://127.0.0.1:45678`。
- 前端使用 Vite；`/api` 代理到后端。开发端口必须先检查，不能假定 `5173` 空闲。
- 后端普通接口返回 `{"data": ...}`，错误返回 `{"details": "..."}`。任务输出优先通过 `/task/:id`、`/task/:id/output` 和 SSE 校验。

## 验证顺序

1. 检查两个仓库的 `git status`，保留已有修改。
2. 运行后端测试。需要测试 MySQL 时，通过用户提供或当前环境已有的 `GO_ALIYUNMC_TEST_MYSQL_*` 注入凭据，不打印凭据。
3. 运行前端 `npm run typecheck` 和 `npm run build`。
4. Docker 可用时运行 `atlas migrate diff --env mysql check`。
5. 启动后端后等待 `/` 返回 200，再启动前端并等待页面可访问。
6. 优先通过 API 创建/部署资源，通过真实任务和 SSE 等待终态，不直接把构造数据写进开发数据库。
7. 涉及 Toast、弹窗、按钮状态或错误详情时，必须执行真实浏览器 UI 验证，不能只验证 API。
8. 完成后恢复故障配置、停止开发进程、清理临时文件，并确认端口无残留监听。

## 真实错误场景

优先使用确定、可逆、成本低的故障注入，并始终保留备份：

- 验证 Minecraft 日志透传时，将 `eula.txt` 临时改为 `eula=false`。启动任务应失败，任务 `error` 应包含 `Minecraft latest.log` 和原始 EULA 错误；随后恢复文件并重新启动服务器。
- 验证远程命令 stderr 透传时，可临时移除 `start.sh` 执行权限。任务 `error` 应包含实际退出码和 `Permission denied`；随后立即恢复权限。
- 不要依赖时序竞争制造端口冲突。竞态场景容易产生无效 E2E；必须复现时先设计确定性屏障和超时。
- 故障注入和业务任务分开执行。备份、修改、触发、检查、恢复逐项确认；失败也必须执行恢复。
- 验证前端时，让同一错误从 UI 触发，并同时检查 Toast 的简短摘要和任务详情中的完整原文。

## 前端与代理诊断

- 使用 Playwright CLI 操作本地页面，先 snapshot 再引用元素；每次导航或重要弹窗变化后重新 snapshot。
- 页面请求必须经过 Vite `/api` 代理。若出现“未知返回结构”，同时检查后端收到的状态码和代理后的响应体。
- 浏览器请求带 `Origin`，curl 默认不带。诊断 CORS 时必须用相同 `Origin`、`Referer` 和 Cookie 比较直连后端与 Vite 代理行为。
- 开发代理应移除 `Origin` 再转发，避免后端 CORS 返回空 403；前端请求层也必须处理非 JSON、空响应和非 200 状态，不能统一报“未知返回结构”。
- 解析外部或动态响应时，不假设可选字段一定存在。例如服务器离线时 Query 的 `plugins` 可能缺失，应返回空插件列表而不是抛异常。
- 前端发现协议兼容或错误展示问题时直接修复并重新跑该 UI 场景；不要把它归为验证范围外。

## 资源清理

- 删除开发实例使用已授权的 `DELETE /instance/active`，随后请求 `/instance/active` 并确认返回 404。
- 删除实例前确认没有创建、部署、启动、启动游戏、备份或归档任务仍在运行。
- 停止自己启动的后端、前端和 Playwright 进程；不要使用宽泛的 `pkill`。
- 临时 Cookie、响应、浏览器快照和日志必须清理。macOS 优先使用 `trash`，不要使用 `rm -rf`。
- 最终报告验证通过项、错误场景、资源清理结果和仍存在的风险或未覆盖项。
