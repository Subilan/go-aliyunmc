# 一键启动游戏

`oneclick_start_game` 在一条任务记录内把服务器带到已部署且在线的终态。它复用创建实例、部署与启动服务器三个任务函数，共用同一个 `TaskContext`，因此只有一条任务记录与一个 SSE 输出流。

## 阶段

一键启动只用于从零开始创建并启动服务器，触发时按固定顺序执行三个阶段：

| 阶段 | 执行内容 |
|---|---|
| 1/3 | 创建实例并等待 SSH 可用 |
| 2/3 | 部署环境 |
| 3/3 | 启动服务器 |

## 完成通知

任务成功结束后，会把 `server_started` 消息模板渲染后异步推送到 QQ 群，默认文本为「服务器已开启~」。
模板位于 `$GO_ALIYUNMC_STATE_DIR/config/messages.toml`，修改方式见 [机器人消息推送](bot-message-api.md)。
推送失败只记录日志，不影响任务结果，也不会把任务标记为失败。

## 已有实例时拒绝触发

触发前会检查是否存在活跃实例。已有实例时任务不会创建、也不会以任何形式改动现有实例，而是直接返回
`409`：

```json
{"details": "已存在活跃实例"}
```

因此一键启动不会续跑已完成部分。创建实例失败时会删除已创建的资源；部署失败时会在标记失败后
best-effort 删除实例，可以直接重新一键启动；启动服务器失败时实例会保留，可以改用
[任务执行与生命周期](tasks.md) 中的启动服务器任务继续完成。

## 权限

创建新实例时沿用创建实例任务的权限规则，普通用户只能使用默认交换机与最佳实例候选，自定义规格需要更高权限。
已有实例时由于会直接拒绝，不再执行创建规格的权限检查，以保证调用方看到「已存在实例」而不是「权限不足」。

## 参数补全

`normalizeOneClickStartGameArgs` 会强制 `startWhenCreated = true`，因为后续部署与启动步骤依赖实例已经启动。未指定 `vSwitchId` 时它会设置 `useDefaultVSwitch = true`，因此调用方可以不带参数触发。

任务执行与互斥规则见 [任务执行与生命周期](tasks.md)。
