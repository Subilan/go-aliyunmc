# 一键启动游戏

`oneclick_start_game` 在一条任务记录内把服务器带到已部署且在线的终态。它复用创建实例、部署与启动服务器三个任务函数，共用同一个 `TaskContext`，因此只有一条任务记录与一个 SSE 输出流。

## 阶段与幂等

每次触发先读取当前实例状态，只执行尚未完成的阶段。

| 当前状态 | 执行内容 |
|---|---|
| 没有实例 | 创建实例、部署环境、启动服务器 |
| 有实例但未部署 | 部署环境、启动服务器 |
| 实例已部署 | 启动服务器 |
| 服务器已在线 | 直接成功返回 |

失败后再次触发会从失败点继续。前端始终只需要一个启动游戏入口，不必根据实例状态切换任务类型。

服务器在线检查只在触发前实例就已存在时进行。刚创建的实例可能仍对应上一个实例留下的状态快照，不能据此判定服务器已经在线。

## 权限

创建新实例时沿用创建实例任务的权限规则，普通用户只能使用默认交换机与最佳实例候选，自定义规格需要更高权限。已有实例时只做续跑，不再检查创建规格的权限。

## 参数补全

`normalizeOneClickStartGameArgs` 会强制 `startWhenCreated = true`，因为后续部署与启动步骤依赖实例已经启动。未指定 `vSwitchId` 时它会设置 `useDefaultVSwitch = true`，因此调用方可以不带参数触发。

任务执行与互斥规则见 [任务执行与生命周期](tasks.md)。
